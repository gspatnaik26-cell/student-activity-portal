Accessibility Audit Report
1. Project Details

Project Name: Student Activity Management Portal

Experiment: Lab Experiment 1 – Semantic, Accessible HTML & the Browser Model

Audit Tool: Google Chrome Lighthouse

Audit Category: Accessibility

Technology Used: HTML5 and CSS3

2. Objective

The objective of this accessibility audit is to evaluate the Student Activity Management Portal webpage and identify possible accessibility issues.

The audit checks whether the webpage is accessible and usable for different categories of users, including people with disabilities.

3. Accessibility Tests Performed
S.No	Accessibility Test	Expected Result
1	Document language	Passed

3	Form labels	Passed
4	Heading hierarchy	Passed
5	Keyboard navigation	Manual verification
6	Link accessibility	Passed
7	Color contrast	Verify using Lighthouse
8	Viewport configuration	Passed
9	Semantic HTML structure	Passed
10	Focus visibility	Passed
4. Accessibility Features Implemented
Used semantic HTML5 elements such as header, nav, main, section, article, aside and footer.
Added proper labels for all form controls.
Used fieldset and legend to group related form elements.
Implemented keyboard navigation.
Added visible focus indicators.
Used appropriate heading hierarchy.
Added required attributes to mandatory form fields.
Configured the webpage for responsive display.
5. Lighthouse Audit Procedure
Opened the Student Activity Management Portal in Google Chrome.
Opened Developer Tools using the F12 key.
Selected the Lighthouse tab.
Selected the Accessibility category.
Selected the Desktop or Mobile option.
Clicked Analyze page load.
Examined the accessibility score and audit results.
Reviewed the warnings and recommendations.
6. Audit Results

Actual Accessibility Score: 100 / 100

Number of Passed Audits: 23

Number of Failed Audits: 0

Number of Manual Checks: 0

Observations

The webpage was designed using semantic HTML5 elements and accessible form controls.

Proper labels, keyboard focus indicators and heading hierarchy were implemented.

The Lighthouse audit was used to evaluate accessibility and identify areas that may require improvement.

7. Recommendations
Maintain sufficient color contrast between text and background.
Ensure all interactive elements are keyboard accessible.
Use meaningful labels for form controls.
Test the webpage using a screen reader.
Correct any accessibility warnings identified by Lighthouse.
8. Conclusion

The accessibility audit was performed on the Student Activity Management Portal using Google Chrome Lighthouse.

The webpage follows basic accessibility guidelines through semantic HTML, proper form labels, keyboard navigation and visible focus indicators.

Thus, the accessibility audit helped evaluate the webpage and identify possible improvements in usability and accessibility.
